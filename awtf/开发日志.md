# AWTF 开发日志

> **AWTF（A Work Tool Framework）** —— 让用户用 Python 代码设计、搭建自己需要的工具与程序的框架。
> 核心原则：写一个函数就是一个工具，自动获得参数校验、错误处理、日志、配置、CLI 与自动文档。

YAML 配置为可选依赖。

### 核心设计：单链路架构

借鉴既往工具系统经验，确立端到端单一链路（避免多入口不一致）：

```
工具定义（@tool / ToolBase / async def）
  → ToolRegistry.register（名称冲突检测 / 版本记录）
  → registry.run(name, params)  ← 唯一执行入口
      → ParameterSet.validate（类型转换 + 约束，聚合全部字段错误）
      → ToolContext.create（注入 logger/config/metadata）
      → 执行（同步直调；异步 asyncio.run 自动调度；可选日志捕获）
      → 异常包装（普通异常 → ToolExecutionError 含 traceback）
  → ToolResult（ok/data/error/duration_ms/metadata/logs）
```

### 关键设计决策

1. **三种工具形态覆盖不同复杂度**：函数工具（`@tool`，注解推断参数，90% 场景）、
   类工具（ToolBase + 显式 ParameterSet，需要状态/复杂校验）、异步工具（`async def`，
   运行器自动事件循环）。装饰后的函数仍可像普通函数直接调用。

2. **参数系统是单一真源**：校验、CLI 帮助、自动文档全部从 ParameterSet 生成；
   校验错误**一次性聚合**（field_errors 字典），而非报一个停一个；
   传 `default` 自动变可选（sentinel 区分"未给默认"与"默认就是 None"）。

3. **工具不把业务异常抛给调用方**：run 默认返回 `ok=False` 的 ToolResult
   （含 error code/traceback），也支持 `raise_on_error=True` 异常模式；
   CLI 据此给出正确退出码。

4. **发现机制三档**：目录扫描（开发期）、模块导入、setuptools entry points（打包发布），
   entry point 工厂可返回 Tool/ToolRegistry/可迭代，自动吸收。

5. **CLI 与 Python API 走同一条链路**：CLI 只做参数解析和结果渲染，
   不绕过校验/异常处理；`--discover` 放在工具名前后都能用
   （REMAINDER 会吞掉后置开关，用专门的提取器捞回）。

### 调试过程中的修复（TDD 驱动）

1. `Parameter('x', int, default=10)` 仍判必填 → 引入 `_UNSET` sentinel，
   传 default 自动 required=False
2. 方法签名 `(self, ctx, x)` 推断只跳过一个前导参 → 改 while 循环跳过 self/ctx/context
3. `from __future__ import annotations` 下注解为字符串 → get_type_hints 解析，
   失败时用 `vars(typing)` + 函数 globals 降级 eval
4. asyncio.get_event_loop() 废弃警告 → 改用 asyncio.run + get_running_loop 判断
5. CLI `run` 的 REMAINDER 吞掉后置 `--discover/--dry-run` → 加 `_extract_discover_flags`
6. 脚手架模板用 str.format 与代码花括号冲突 → 改 string.Template（$占位符）

### 重大坑：awtf import 被 namespace 抢占
现象：cwd=c:\Aovow 时 `import awtf` 得到 **namespace 包**（`file: None`，location `C:\Aovow\awtf`），导致 `from awtf import Parameter` 报 `unknown location`。
根因：editable 安装的 finder 是 **append 到 sys.meta_path 末尾**；`PathFinder` 先在 cwd 命中 `C:\Aovow\awtf`（无 `__init__.py` → namespace spec）并**直接返回**，不再继续到 editable finder。
修复：在入口与工具文件顶部引导**真包父目录** `c:\Aovow\awtf` 进 `sys.path`，PathFinder 即可命中 `awtf\awtf\__init__.py` 真包。
（注意：引导的是父目录 `…/awtf`，不是 `…/awtf/awtf`；后者只会再造一个 namespace。）
