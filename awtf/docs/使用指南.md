## 1. AWTF 是什么

AWTF 让你**用 Python 代码设计自己需要的工具与程序**——"写一个函数"就等于"做了一个工具"，并自动附赠：

- **参数校验**：类型自动转换、必填/默认、枚举、范围、长度、正则；
- **错误处理**：工具报错自动包装成结构化结果（含 traceback），不会崩掉调用方；
- **日志**：每个工具有独立 logger，执行日志可随结果返回；
- **配置**：配置文件 + 环境变量分层合并；
- **CLI**：命令行 `list / info / run / new / docs / doctor` 开箱即用；
- **自动文档**：参数 schema、Markdown 文档自动生成；
- **可发布**：第三方包可通过 entry points 被自动发现。

执行链路只有一条（CLI 和 Python 代码走的是同一条）：

```
工具定义（@tool / ToolBase）
   → 注册表 ToolRegistry
   → registry.run(工具名, 参数)
       → 参数转换与校验（一次性收集所有错误）
       → 注入上下文 ctx（logger/config/metadata）
       → 执行（同步/异步自动调度）
   → ToolResult（ok / data / error / 耗时 / 日志）
```

## 2. 安装与环境自检

### 2.1 安装

awtf 核心只依赖 Python 标准库。两种方式：

```bash
# 方式 A：直接用源码（把项目目录放到 Python 能找到的位置，或设置 PYTHONPATH）
set PYTHONPATH=C:\Aovow\awtf;%PYTHONPATH%      # Windows PowerShell: $env:PYTHONPATH="C:\Aovow\awtf"

# 方式 B：安装到当前 Python 环境
cd C:\Aovow\awtf
pip install .
```

可选依赖（仅在用到时需要）：

```bash
pip install pyyaml    # 想用 YAML 配置文件时
pip install pytest    # 想跑单元测试时
```

> Windows 提示：如果系统默认 `python` 缺包，请用 Anaconda 的 Python，
> 例如 `C:\Users\lshen\anaconda3\python.exe -m awtf doctor`。

### 2.2 环境自检

```bash
python -m awtf doctor
```

输出类似：

```

  [✓] yaml
  [✓] pytest
```

## 3. 5 分钟：生成并运行第一个工具

### 第 1 步：用脚手架生成工具

```bash
python -m awtf new hello --dir my_tools --description "打招呼工具"
```

会生成：

```
my_tools/
├── tools_hello.py   # 工具代码（改这个文件）
└── README.md        # 使用说明
```

打开 `tools_hello.py`，核心是一个带 `@tool` 装饰的函数：

```python
from awtf import Parameter, ToolContext, tool

@tool(
    name="hello",
    version="0.1.0",
    tags=["custom"],
    parameters=[
        Parameter("text", str, description="输入文本", min_length=1),
        Parameter("repeat", int, default=1, min=1, max=10, description="重复次数"),
    ],
)
def hello(ctx: ToolContext, text: str, repeat: int = 1) -> dict:
    """打招呼工具"""
    ctx.info("执行 hello: text=%s repeat=%s", text, repeat)
    if ctx.dry_run:
        return {"would_do": f"把 {text!r} 重复 {repeat} 次"}
    return {"tool": "hello", "input": text,
            "output": (text + " ") * repeat, "repeat": repeat}
```

### 第 2 步：命令行直接运行

```bash
# 查看工具列表
python -m awtf list --discover my_tools

# 查看参数说明
python -m awtf info hello --discover my_tools

# 运行（--discover 放工具名前后都可以）
python -m awtf run hello --text "世界" --repeat 2 --discover my_tools
```

返回 JSON：

```json
{
  "tool": "hello",
  "ok": true,
  "data": {"tool": "hello", "input": "世界", "output": "世界 世界 ", "repeat": 2},
  "duration_ms": 0.07,
  ...
}
```

演练模式（不产生真实副作用）：

```bash
python -m awtf run hello --text "测试" --dry-run --discover my_tools
```

### 第 3 步：在 Python 代码中调用

```python
from awtf import ToolRegistry

registry = ToolRegistry()
registry.discover_path("my_tools")          # 发现目录里的所有工具

result = registry.run("hello", {"text": "世界", "repeat": 3})
if result.ok:
    print(result.data["output"])            # 世界 世界 世界
else:
    print("失败：", result.error["message"])
```

恭喜，你已经完成了一个工具的全流程。

## 4. 写工具的三种方式

### 4.1 函数工具（推荐，90% 场景）

写一个普通函数，第一个参数固定为 `ctx`，加上 `@tool`：

```python
from awtf import tool, ToolContext

@tool(name="word_count", tags=["text"])
def word_count(ctx: ToolContext, text: str, language: str = "en") -> dict:
    """统计文本词数。

    Args:
        text: 待统计文本
        language: en 按空格分词；zh 按中文字符计
    """
    count = len([c for c in text if "\u4e00" <= c <= "\u9fff"]) if language == "zh" \
        else len(text.split())
    ctx.info("统计完成：%d 词", count)
    return {"words": count, "chars": len(text)}
```

要点：

- **参数类型从注解自动推断**：`text: str`、`language: str = "en"` 自动成为必填/可选参数；
- **docstring 的 `Args:` 段会自动变成参数说明**（也支持 Sphinx 风格 `:param x:`）；
- 装饰后的函数**仍可像普通函数一样直接调用**：`word_count(ctx, text="hi")`；
- 工具的**首行 docstring 自动成为工具描述**（也可用 `@tool(description=...)` 覆盖）。

### 4.2 类工具（需要状态、复杂参数、生命周期）

继承 `ToolBase`，显式声明 `parameters`，实现 `run`：

```python
from awtf import ToolBase, Parameter, ParameterSet, ToolContext, ToolConfigError
import pathlib

class OrganizeDirTool(ToolBase):
    name = "organize_dir"
    description = "按扩展名归类文件"
    tags = ("files",)

    parameters = ParameterSet([
        Parameter("dir", "path", description="目标目录"),
        Parameter("recursive", bool, default=False, description="是否递归子目录"),
    ])

    def run(self, ctx: ToolContext, dir: pathlib.Path, recursive: bool = False) -> dict:
        if not dir.exists():
            raise ToolConfigError(f"目录不存在: {dir}")   # 业务错误主动抛出
        files = list(dir.rglob("*") if recursive else dir.iterdir())
        ctx.info("发现 %d 个文件", len([f for f in files if f.is_file()]))
        ...
        return {"total_files": len(files)}
```

类工具适合：需要保存连接/缓存、参数需要显式精细控制、想在一个类里放多个辅助方法。

### 4.3 异步工具（并发 IO）

定义为 `async def` 即可，注册表自动调度事件循环，**调用方式完全不变**：

```python
import asyncio
from awtf import tool, ToolContext

@tool(name="sleep_sort", tags=["async"])
async def sleep_sort(ctx: ToolContext, numbers: list) -> dict:
    """异步演示。"""
    async def delayed(n):
        await asyncio.sleep(n / 100)
        return n
    results = await asyncio.gather(*(delayed(float(n)) for n in numbers))
    return {"sorted": sorted(results)}
```

## 5. 参数系统全解

参数是工具的"输入合同"。声明方式有两种：

- **自动推断**：函数注解 + 默认值 + docstring（最简单）；
- **显式声明**：`Parameter(...)`（需要约束时）。

### 5.1 支持的类型

| 类型 | 注解写法 | CLI 传入示例 | 转换结果 |
|------|----------|--------------|----------|
| 字符串 | `str` | `--name 张三` | `"张三"` |
| 整数 | `int` | `--count 3` | `3` |
| 浮点 | `float` | `--rate 0.8` | `0.8` |
| 布尔 | `bool` | `--flag true` | `True`（也接受 yes/on/1/是） |
| 列表 | `list` | `--tags a,b,c` 或 `--tags '["a","b"]'` | `["a","b","c"]` |
| 字典 | `dict` | `--data '{"k":1}'` | `{"k": 1}` |
| 路径 | `pathlib.Path` 或 `"path"` | `--dir ~/docs` | `Path("~/docs").expanduser()` |
| 可选 | `Optional[str]` | 不传 | `None` |

### 5.2 校验约束

```python
Parameter("age",   int,  min=0, max=120)                 # 数值范围
Parameter("role",  str,  choices=["admin", "user"])      # 枚举
Parameter("code",  str,  pattern=r"^\d{4}$")             # 正则
Parameter("name",  str,  min_length=2, max_length=20)    # 长度
Parameter("token", str,  required=True, secret=True)     # 敏感值（日志脱敏）
```

必填规则：

- **没有默认值 → 必填**；给了 `default=...` → 自动可选；
- 可用 `required=True/False` 显式覆盖。

### 5.3 校验失败长什么样

错误会**一次性收集所有字段问题**（不是报一个停一个）。例如调用缺参数、类型错、越界：

```python
result = registry.run("add", {"count": "abc", "age": 999})
# result.error["code"] == "VALIDATION_ERROR"
# result.error["details"]["field_errors"] == {
#   "name":  "缺少必填参数",
#   "count": "无法转换为整数: 'abc'",
#   "age":   "数值 999 大于最大值 120",
# }
```

传入未声明的参数会产生 `__unknown__` 错误，帮助发现拼写错误。

## 6. 运行工具：Python API

### 6.1 基本调用

```python
from awtf import ToolRegistry

registry = ToolRegistry()
registry.discover_path("my_tools")          # 或 register(tool) / discover_module("pkg")

result = registry.run(
    "hello",                                # 工具名
    {"text": "世界", "repeat": 2},          # 参数字典（会自动转换/校验）
    config={"hello": {"greeting": "你好"}},  # 可选：配置
    metadata={"source": "web", "request_id": "req-001"},  # 可选：元数据
    capture_logs=True,                      # 可选：捕获执行日志
)
```

### 6.2 常用写法

```python
# 用装饰器在定义时直接注册到自己的注册表
registry = ToolRegistry()

@registry.tool(tags=["math"])
def add(ctx, a: int, b: int = 1) -> int:
    """两数相加。"""
    return a + b

registry.run("add", {"a": 1, "b": 2})       # data == 3
registry.run("add", {"a": "10"})            # 字符串自动转 int，b 用默认值 → 11

# 进程级单例注册表（多处共享）
from awtf import get_default_registry
reg = get_default_registry()
```

### 6.3 查询工具

```python
registry.names()                            # ["add", "hello", ...]
registry.has("add")                         # True
registry.list_tools(tag="math")             # 按标签过滤
registry.describe("add")                    # 完整 schema（元数据+参数）
```

### 6.4 工具内读取上下文

```python
def my_tool(ctx: ToolContext):
    ctx.info("普通日志")                      # 也有 debug/warning/error
    value = ctx.get_config("timeout", 30)    # 读同名配置段里的键
    cfg = ctx.section_config("my_tool")      # 取整个配置段
    if ctx.dry_run:                         # 演练模式
        return {"would_do": "..."}
```

## 7. 运行工具：命令行 CLI

### 7.1 命令一览

```bash
python -m awtf list     [--discover 目录或文件] [--tag xxx] [--json]
python -m awtf info     <工具名> [--discover ...]
python -m awtf run      <工具名> [--参数 值 ...] [--dry-run] [-v] [--json] [--discover ...]
python -m awtf new      <工具名> [--dir 目录] [--description "说明"] [--no-readme]
python -m awtf docs     [工具名] [--discover ...]     # 输出 Markdown 文档
python -m awtf doctor
```

### 7.2 参数传递规则

- 形式：`--键 值`，也支持 `--键=值`；
- 值会**先尝试按 JSON 解析**，失败再当字符串：

```bash
python -m awtf run calc --a 3 --b 4.5 --flag true --tags '["x","y"]' --discover .
# → a=3(int)  b=4.5(float)  flag=True  tags=["x","y"](list)
```

- `--discover` 放在工具名**前面或后面都行**；
- `--dry-run` 演练、`-v/--verbose` 显示日志与 traceback、`--json` 强制 JSON 输出。

### 7.3 退出码（便于写脚本）

| 退出码 | 含义 |
|--------|------|
| 0 | 执行成功 |
| 1 | 工具执行失败（校验失败、运行报错） |
| 2 | 用法错误（工具不存在、文件冲突等） |

示例（PowerShell 判断）：

```powershell
python -m awtf run hello --text hi --discover my_tools
if ($LASTEXITCODE -eq 0) { "成功" } else { "失败" }
```

## 8. 结果对象与错误处理

`registry.run()` **永远返回 `ToolResult`，默认不抛业务异常**。

### 8.1 结果字段

```python
result.ok            # True/False
result.data          # 成功时的返回值
result.error         # 失败时：{"code","message","tool","details"}
result.duration_ms   # 耗时（毫秒）
result.metadata      # 你传入的元数据
result.logs          # capture_logs=True 时的日志行列表
result.to_dict()     # 转 JSON 安全字典（CLI/网络回传）
result.get("k")      # data 是字典时按键取值
```

### 8.2 两种错误处理风格

```python
# 风格 A：判断结果（默认，适合 CLI/服务）
result = registry.run("risky", params)
if not result.ok:
    print(result.error["code"])       # 如 VALIDATION_ERROR
    print(result.error["message"])

# 风格 B：异常模式
from awtf import ToolValidationError, ToolExecutionError, ToolNotFoundError
try:
    result = registry.run("risky", params, raise_on_error=True)
except ToolValidationError as e:
    print(e.field_errors)             # 所有字段错误
except ToolExecutionError as e:
    print(e.traceback_text)           # 完整 traceback
except ToolNotFoundError as e:
    print(e.details["available"])     # 可用工具列表
```

### 8.3 错误码表

| code | 触发场景 | 关键 details |
|------|----------|--------------|
| `VALIDATION_ERROR` | 参数缺失/类型错/违反约束 | `field_errors`（每个字段的原因） |
| `TOOL_NOT_FOUND` | 工具未注册 | `available`（当前可用工具名） |
| `EXECUTION_ERROR` | 工具内部抛了异常 | `exception_type` / `exception_message` / `traceback` |
| `CONFIG_ERROR` | 配置缺失/格式错 | `section` / `key` |
| `REGISTRATION_ERROR` | 重名注册、注册了未装饰的函数 | `existing_version` / `new_version` |
| `DISCOVERY_ERROR` | 发现路径不存在/导入失败 | `path` / `file` |

工具内部**主动抛 `ToolError` 子类会被原样保留**；抛普通 `ValueError` 等会被自动包装为
`EXECUTION_ERROR`（含 traceback），不会击穿调用方。

## 9. 配置管理

优先级：**默认值 < 配置文件 < 环境变量**。

### 9.1 配置文件（JSON）

```json
// config.json
{
  "backup": { "target_dir": "D:\\archive", "keep_days": 30 },
  "app_name": "my-tools"
}
```

### 9.2 环境变量覆盖

规则：`AWTF__段名__键名=值`，值按 JSON 解析：

```bash
set AWTF__BACKUP__KEEP_DAYS=60        # 覆盖 backup.keep_days
set AWTF__APP_NAME='"cli"'            # 字符串
```

### 9.3 加载与传入

```python
from awtf import load_config

config = load_config(
    "config.json",                         # 配置文件（.json；.yaml 需 pip install pyyaml）
    defaults={"backup": {"keep_days": 7}}, # 内置默认值
)

registry.run("backup", {...}, config=config)
```

### 9.4 工具内读取

```python
from awtf import ToolContext

def backup(ctx: ToolContext, ...):
    keep = ctx.section_config("backup").get_int("keep_days", 7)
    target = ctx.get_config("target_dir", required=True)   # 缺失会抛 CONFIG_ERROR
```

`ToolConfig` 提供 `get / get_str / get_int / get_float / get_bool`，支持 `required=True`。

## 10. 日志

```python
from awtf import setup_logging

setup_logging("INFO", log_file="tools.log")   # 控制台 + 文件（只需调用一次）
```

- 每个工具有独立 logger：`awtf.tools.<工具名>`，工具内直接用 `ctx.info(...)`；
- 把一次执行的日志收集进结果（适合在界面/接口里展示）：

```python
result = registry.run("hello", {...}, capture_logs=True)
print(result.logs)        # ["[INFO] 执行 hello: ..."]
```

CLI 加 `-v` 即可看到这些日志和失败时的 traceback。

## 11. 工具发现与打包发布

### 11.1 三种发现方式

```python
registry.discover_path("my_tools/")              # 扫描目录下所有 .py
registry.discover_path("my_tools/tools_hello.py")# 单个文件
registry.discover_module("my_pkg.tools")         # 导入已安装的模块
registry.discover_entry_points()                 # 发现已安装包注册的工具
```

发现规则：模块内所有被 `@tool` 装饰的函数、`ToolBase` 子类/实例都会自动注册
（下划线开头的文件会被跳过）。

### 11.2 打包发布给别人用

在你的包的 `pyproject.toml` 声明 entry point：

```toml
[project.entry-points."awtf.tools"]
my_bundle = "my_pkg.tools:register_tools"
```

`register_tools` 可以是：一个 `ToolBase` 实例、一个 `ToolRegistry`、或返回它们的工厂函数。
用户安装你的包后：

```python
registry = ToolRegistry()
registry.discover_entry_points()     # 你的工具自动出现
registry.names()
```

CLI 也支持：`python -m awtf list --entry-points`。

### 11.3 重名冲突

同名工具重复注册默认报错（`REGISTRATION_ERROR`，提示新旧版本）。确需覆盖：

```python
registry.register(tool, override=True)
```

## 12. 完整实战：写一个文件备份工具

目标：把目录里的文件按修改日期备份到目标目录，支持配置、演练、日志。

**第 1 步：生成骨架**

```bash
python -m awtf new backup --dir my_tools --description "按日期备份文件"
```

**第 2 步：改写 `my_tools/tools_backup.py`**

```python
from __future__ import annotations
import datetime as dt
import pathlib
import shutil

from awtf import Parameter, ToolContext, tool


@tool(
    name="backup",
    version="1.0.0",
    tags=["files", "backup"],
    parameters=[
        Parameter("src", "path", description="源目录", min_length=1),
        Parameter("dst", "path", description="备份根目录", min_length=1),
        Parameter("pattern", str, default="*", description="文件匹配模式"),
        Parameter("dry", bool, default=False, description="只演练不复制"),
    ],
)
def backup(ctx: ToolContext, src: pathlib.Path, dst: pathlib.Path,
           pattern: str = "*", dry: bool = False) -> dict:
    """按文件修改日期把源目录文件备份到 目标目录/YYYY-MM-DD/。"""
    if not src.exists() or not src.is_dir():
        raise FileNotFoundError(f"源目录不存在: {src}")

    today = dt.date.today().isoformat()
    target_dir = dst / today
    files = [f for f in src.glob(pattern) if f.is_file()]

    ctx.info("源 %s 共 %d 个文件，目标 %s", src, len(files), target_dir)

    copied = []
    if not dry and not ctx.dry_run:
        target_dir.mkdir(parents=True, exist_ok=True)
        for f in files:
            shutil.copy2(f, target_dir / f.name)
            copied.append(f.name)
            ctx.debug("已复制 %s", f.name)

    return {
        "source": str(src),
        "target": str(target_dir),
        "matched": len(files),
        "copied": len(copied),
        "dry_run": dry or ctx.dry_run,
        "files": [f.name for f in files],
    }
```

```bash
# 确认无误后真实执行
```

## 13. FAQ 常见问题

**Q1：必须用 CLI 吗？**
不用。CLI 只是薄壳，核心是 Python API。CLI 和代码走同一条校验/错误链路。

**Q2：参数一定要写 `Parameter(...)` 吗？**
不用。函数注解 + 默认值就能自动推断；只有需要枚举/范围/正则等约束时才显式写。

**Q3：工具里能抛异常吗？**
可以。抛 `ToolError` 子类（如 `ToolConfigError`）会原样保留错误码；抛普通异常会被包装成
`EXECUTION_ERROR` 并附带 traceback，调用方不会崩。

**Q4：异步工具怎么调用？**
和同步完全一样——`registry.run("name", {...})`，注册表自动处理事件循环。

**Q5：工具名重复了怎么办？**
默认报 `REGISTRATION_ERROR` 防止误覆盖；确认要覆盖用 `register(tool, override=True)`。

**Q6：怎么让别人 pip install 后就能用我的工具？**
在包的 `pyproject.toml` 里声明 `[project.entry-points."awtf.tools"]`，
指向你的工具/注册表工厂函数（见第 11 节）。

**Q7：配置支持 YAML 吗？**
支持，但需 `pip install pyyaml`；不装时用 JSON 即可（核心零依赖）。

**Q8：`--discover` 写在工具名后面识别不到？**
已支持，工具名前后都可以；若仍异常，升级到最新版或把 `--discover` 放在 `run` 后、工具名前。

**Q9：Windows 下提示 `No module named yaml/pytest`？**
那是可选依赖；核心功能不受影响。用已装好依赖的 Python 环境，或 `pip install pyyaml pytest`。
